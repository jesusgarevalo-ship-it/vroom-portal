VROOM Repuestos Express

Especificación Técnica — Phase 1 MVP

1. Resumen Ejecutivo

Repuestos Express es el módulo MVP de VROOM — la primera plataforma de repuestos automotrices en Venezuela con búsqueda por lenguaje natural, entrega en 15 minutos y pago vía Pago Móvil. No es un marketplace genérico: es un sistema de confianza donde cada repuesto está verificado, cada conductor es rastreado, y cada transacción es transparente.

🎯 Meta Phase 1

500 transacciones/mes · NPS > 50 · Break-even $12K MRR (Mes 8-10)

🏙️ Cobertura

Caracas + Maracaibo · 50 proveedores · 2 ciudades iniciales

💳 Pago

Pago Móvil BS (Banesco, Venezuela, Bicentenario)

⏱️ Entrega

Exprés 15-30 min · Rastreo en tiempo real · GPS

4.2 Funciones de Búsqueda IA (pg_trgm)

-- Crear search_vector para productos
CREATE OR REPLACE FUNCTION products_search_trigger()
RETURNS TRIGGER AS $$
BEGIN
    NEW.search_vector :=
        setweight(to_tsvector('spanish', COALESCE(NEW.name, '')), 'A') ||
        setweight(to_tsvector('spanish', COALESCE(NEW.brand, '')), 'B') ||
        setweight(to_tsvector('spanish', COALESCE(NEW.description, '')), 'C') ||
        setweight(to_tsvector('spanish',
            COALESCE(NEW.compatibility->>'vehicles', '')), 'B');
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER products_search_update
    BEFORE INSERT OR UPDATE ON products
    FOR EACH ROW EXECUTE FUNCTION products_search_trigger();

6. IA para Búsqueda — Phase 1

6.1 Parser de Lenguaje Natural

No usamos ML pesado en Phase 1. usamos reglas + PostgreSQL full-text + fuzzy matching. Esto es suficiente para arrancar con 50 proveedores y genera resultados relevantes de inmediato.

// Ejemplo: "pastillas de freno civic 2019"
INPUT: "pastillas de freno civic 2019"

// Tokenización + stemming (spanish)
tokens = ["pastilla", "freno", "civic", "2019"]

// Mapeo de patrones:
patterns = {
  /\d{4}/ → year: "2019",
  /civic|corolla|sentra|spark|onix/i → vehicle: "Honda Civic",
  /pastilla.*freno|freno.*pastilla/i → part: "pastillas de freno",
  /delantera|trasera|front|rear/i → position: "delanteras",
  /original|oem|genuine/i → type: "OEM"
}

// Resultado:
{
  "vehicle": "Honda Civic",
  "year": 2019,
  "part": "pastillas de freno",
  "position": "delanteras",
  "query_tokens": ["pastilla", "freno", "civic"],
  "confidence": 0.92
}

6.2 Pipeline de Búsqueda

  1. Parsear query — extraer vehículo, año, pieza, categoría del texto libre
  2. Búsqueda full-text — ts_headline con Spanish dictionary en search_vector
  3. Fuzzy matching — pg_trgm para typos ("pastilhas" → "pastillas")
  4. Filtro geográfico — solo proveedores en la ciudad del usuario
  5. Rankeo — proximity_score × (1 / distance_km) × stock_availability × supplier_rating
  6. "¿Quisiste decir?" — si no hay resultados, sugerir con trigram distance
-- Query SQL real
SELECT p.*, s.name as supplier_name, s.rating as supplier_rating,
       s.lat, s.lng,
       ts_headline('spanish', p.name, query, 'StartSel=<mark>, StopSel=</mark>') as name_highlight
FROM products p
JOIN suppliers s ON s.id = p.supplier_id
CROSS JOIN plainto_tsquery('spanish', 'pastillas freno civic') query
WHERE p.search_vector @@ query
  AND s.city = 'Caracas'
  AND p.stock > 0
  AND s.active = TRUE
  AND s.verified = TRUE
ORDER BY p.stock > 0 DESC,
         s.rating DESC,
         s.lat <-> point(10.4806, -66.9036)
LIMIT 20;
💡 Phase 2 upgrade: Cuando tengamos +10K productos y +1K búsquedas/día, agregamos pgvector para embeddings semánticos. El schema ya tiene la columna — solo instalamos la extensión y entrenamos embeddings con sentence-transformers.

7. Sistema de Pagos — Solo Pago Móvil

7.1 Flujo de Pago Móvil

1. Orden creada → 2. VROOM genera referencia única → 3. Cliente transfiere por su banco → 4. VROOM verifica referencia → 5. Pago en escrow → 6. Orden confirmada → 7. Entrega completada → liberar a proveedor

7.2 Detalle del Flujo

  1. Crear orden → estado pending, payment_status: pending
  2. POST /payments/initiate → genera referencia "VROOM-ABC123" de 8 caracteres + monto en BS (BCV rate del día + 2%)
  3. Cliente transfiere desde su app del banco (Banesco, Venezuela, Bicentenario, etc.) al teléfono Pago Móvil de VROOM con la referencia
  4. Cliente reporta → POST /payments/confirm con últimos 8 dígitos de la referencia
  5. VROOM verifica:
    • Monto mínimo ($0.50 USD)
    • Monto máximo ($500 USD)
    • Referencia no usada antes
    • Banco emisor no bloqueado
  6. Si pasa → payment_status: held, estado orden confirmed
  7. Si falla 3 veces → orden cancelada, referencia expirada
  8. Entrega completada → payment_status: released → VROOM retiene 15% como fee
  9. Si entrega falla → payment_status: refunded → cliente recibe el monto

9. Autenticación

9.1 Flujo OTP

  1. Usuario ingresa número de teléfono (+58 412 XXX XXXX)
  2. POST /auth/send-otp → código de 6 dígitos generado (crypto random)
  3. Código enviado por SMS (Twilio) o WhatsApp ( Africa's Talking)
  4. Código expira en 5 minutos. Máximo 5 códigos por hora por teléfono
  5. POST /auth/verify-otp → JWT access_token (24h) + refresh_token (30d)
  6. Refresh token rotation: cada uso genera nuevo refresh token
  7. Si 10 intentos fallidos → cuenta bloqueada 30 minutos

9.2 JWT Strategy

// Access Token (24h)
{
  "sub": "user_uuid",
  "phone": "+584121234567",
  "role": "customer",

// On logout: DEL token:{jti}

13. Riesgos y Mitigaciones

🏦 Pago Móvil — banco bloquea cuentas
Mantener 2-3 cuentas rotativas de Pago Móvil. Phase 2: integrarse con aggregador pagomóvil.com.ve que maneja múltiples bancos desde una API.
🌐 Internet inestable en Venezuela
Carrito guardado en localStorage. Cola de órdenes offline. Retry automático con exponential backoff. Optimistic UI para acciones no-críticas.
👥 Adopción de proveedores
Onboarding white-glove: nosotros llamamos al proveedor, configuramos su cuenta, cargamos sus productos. Soporte por WhatsApp directo.
🏍️ Conductores no confiables
Verificación de identidad obligatoria. Rating mínimo 4.0 para activar. Bonos por SLA (llegar a tiempo). Pérdida de acceso si rating baja de 3.5.
📦 Productos incorrectos
Foto del producto en el pedido. Driver toma foto al entregar. Reembolso automático si cliente reporta error dentro de 2 horas.
💱 Tipo de cambio BCV
Rate bloqueado al momento de crear la orden. Buffer del 2% sobre BCV. Si BCV sube +10% durante la orden, absorber con reserva.
